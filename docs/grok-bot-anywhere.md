# Grok Bot Anywhere 交接

把现在的 Mac Touch Bar Bot 做成 Mac 和 Windows 都能用的 Grok Bot Anywhere。登录一个 Grok Bot 账号之后，把指定 Bot 设成接收单位。微信转发、快捷指令、悬浮输入框和 Touch Bar 把上下文交给这个 Bot。收到之后，按该 Bot 的设置直接发送，或先放进输入框补充再发送。

名称的意思是：Grok Bot 可以出现在任何地方，接收传进来的上下文。

## 仓库

| 用途 | 路径 |
|---|---|

| 头像 | `/Users/ronglecat/Documents/workspace/tools/grok-bot-avatar-engine` |

Bot 侧只走 grok-bot-sdk。和操作系统、微信、快捷指令的衔接由本应用做。

## 界面

页面只留能操作的内容。每个控件一种文字，跟随系统语言，同一行不并列中英两套字。

不放协议名、版本号、形状英文名、算法说明、调试字段。

主窗口是 Bot 名单。设置是接收单位和账号。悬浮层是输入框和 Tab 宫格。另有一页收件记录。

## 外观

Mac 和 Windows 用同一套样式。

- 主题：跟随系统、亮色、暗色。
- 亮色画布 `#f4f3f0`，表面约 86% 不透明。暗色画布 `#0b0b0c`，表面约 84% 不透明。
- 窗口用系统毛玻璃或 Acrylic。卡片圆角连续 22pt。分割用发丝线，阴影用暖灰。
- 强调色只有 `#f59312`，用在选中、主按钮和焦点环。
- 字体：苹方、Segoe UI Variable、微软雅黑。

## 头像

所有头像都用 `grok-bot-avatar-engine`。

- 身份用 Bot 的 id。名单里有形状或颜色就用那一项；缺的那项按 id 推导。有头像图片就显示图片。
- 能播动画的表面都播：名单、悬浮输入框、Tab 宫格、设置里的接收单位、Touch Bar。
- 实时头像用 `createAvatar`。Touch Bar 的一条离屏条用 `createStrip`，再切给每个 Bot。
- 主 Bot 星标用 `main: true`。比例保持现在的实现：60 视口里直径 16 的圆盘，贴右下，孔半径 10.7，填充 `#f59312`。
- 微信菜单那一行是系统静态图标，放不进实时画面。更新菜单时用 `capture()` 或 `renderAvatarPng()` 截该 Bot 的一帧，形状和颜色与应用内一致。

## 账号与名单

用 SDK 的 `createLogin` / `pollLogin` 做浏览器登录，`GrokBotClient` 做 `getMe`、`listBots`、`sendMessage`、回复订阅。

Mac 保留现在的「使用本机 Grok Bot 登录」，只读取本机已有的访问令牌。Windows 走浏览器登录。

令牌失效后停下来，请用户重新登录。`SEND_UNCONFIRMED` 停在这一条，不自动重发。

文件由应用自己上传。上传完成后，把服务端引用交给 `sendMessage` 的 `attachmentPaths` 和 `attachmentNames`。SDK 不上传本地字节。

## 接收单位

默认全部关闭。在设置里按 Bot 打开。

| 项 | 选择 |
|---|---|
| 可作为接收单位 | 开或关 |
| 收到之后 | 直接发送，或先放进输入框 |
| 接受来源 | 微信、快捷指令、系统分享、拖放，分开开关 |
| 直接发送的前缀 | 可选的一段固定说明，接在正文前面 |

默认投递是「先放进输入框」。

微信菜单里，开了几个接收 Bot 就有几行，没有第二层选择。其他入口若只有一个启用的 Bot，就直接用它。

回复只出现在本应用的通知和收件记录里，不写回微信。

## 收件

来源先把内容写成一条本地收件，这一步不联网。主程序再按该 Bot 的投递方式处理。

收件记下：来源、时间、文字、文件、能识别到的标题、目标 Bot、当时的投递方式。

- 直接发送：上传文件后 `sendMessage`。超过 90 秒还没发出去，标为过期。
- 先放进输入框：打开悬浮框，预填上下文，用户补字后回车再发。草稿留到发送或关闭。
- 微信合并转发的 ZIP 是主要载荷，不要用旧输入框的 4MiB 上限裁掉它。

收件记录的状态：待补充、已发送、未确认、失败、过期。失败的留下文件，可以重试。

## 微信转发菜单

参考 WeChatBridge：菜单里一行是一个分享扩展。扩展只接收微信自己导出的 ZIP、文本和媒体。不读微信数据库，不解密，不注入，不替用户发微信消息。扩展没有网络权限。

产品要求：

- 打开几个接收 Bot，菜单里就有几行。
- 文案是 `发给 {Bot 名}`，图标是这个 Bot 的头像。
- 关掉的 Bot 不占行，也不留空位。
- 顺序跟设置里的接收单位顺序一致。
- 点这一行就投给这一行绑定的 Bot，再按该 Bot 的投递方式处理。扩展里不再选 Bot。
- 同名 Bot 靠头像区分。名字过长由系统截断。

做法：包里预先放 12 个扩展槽，共用一个扩展程序，靠槽位编号区分。第 13 个 Bot 仍可当接收单位，用悬浮输入框和快捷指令，只是进不了这个菜单。

系统只认签名过的扩展名。设置里改了接收单位、名字或头像之后，做一次「更新微信转发菜单」：写入槽的显示名、头像和 Bot id，重新签名，向系统重新注册。没启用的槽关掉。名字和头像都没变、只是开关某一行时，只切换显示，不必整包重签。签名变过之后，系统可能会要求再次允许这个应用。

Windows 的微信如果也能列出多个分享目标，用同一套槽位。在那台微信上验证通过之前，不把这张 Mac 菜单写成两端都有。Windows 第一期先保证悬浮输入框、拖入 ZIP 和快捷键。

## 快捷指令

Mac 用 App Intents 提供两个动作：

- 把文本发给 Grok Bot：已启用的 Bot，加文本。
- 把文件发给 Grok Bot：已启用的 Bot，加文件。

它们出现在快捷指令、分享菜单和服务里。直接发送的 Bot 在后台完成。先放进输入框的 Bot 唤起悬浮框。

另留 `grokbotanywhere://`，给「打开 URL」用。链接里不放令牌。

Windows 第一期没有等价的系统快捷指令。召唤输入框的全局快捷键两端都有。

## 必须留住的现有交互

这些以现在的 Touch Bar Bot 为准。

| 能力 | 去处 |
|---|---|
| ⌃⌥Space 唤起输入框 | Mac 保留。Windows 用 Ctrl+Alt+Space |
| ⌃⌥V 开始录音，任意键结束并发送 | 仅 Mac |
| 输入框贴在当前屏幕底部，卡片外点击穿透 | 两端 |
| 点按外部关闭、发送后保留或隐藏 | 两端。默认保留 |
| 回车发送，Shift+回车换行 | 两端 |
| 输入法组字或候选窗出现时，回车不发送 | 两端。输入框用各系统的原生文本框 |
| Tab 打开 10 列宫格，最多两行。1–0、− +、方向键、回车和 Tab 确认，Esc 取消 | 两端 |
| 主 Bot 星标，所有头像表面同一比例 | 两端 |
| 常驻 Touch Bar。未选中 30×30，间距 8。选中项显示全名，不省略 | 仅 Mac |
| 拖入文件 | 两端 |

输入框继续用原生文本控件。Mac 是现在的文本视图，Windows 用系统文本框。周围的半透明卡片可以共用样式。文本框不要换成网页输入。

Touch Bar 不要在每一项里放一个网页视图。继续一条离屏画面，按 Bot 切帧。未选中项保持原尺寸，动画时不要把字形放大。正在运行的 Bot 播工作状态。滑动不要闪。

唤醒输入框时贴在当前屏幕下方，底边距离保持固定，发送过程中不要跳位。

## 软件怎么搭

共享界面负责两端看起来一样的窗口：名单、设置、收件记录、主题。

Bot 调用放在随包的 Node 侧，只依赖 grok-bot-sdk。

Mac 另有一个原生伴侣进程，专管 Touch Bar、分享扩展、快捷指令、语音、全局热键、钥匙串和原生输入框。分享扩展或语音不可用时，主窗口仍然能登录和打字。

Windows 第一期是同一个窗口、同一套收件箱和原生输入框。微信分享目标等实机验证后再接。

## 分期

1. 产品名为 Grok Bot Anywhere。两端窗口、登录、名单、现在这套输入框和 Tab 宫格、按 Bot 配置的两种投递。头像接上 `grok-bot-avatar-engine`。
2. Mac 分享扩展进微信转发菜单，快捷指令两个动作，收件记录。
3. 把现在的 Touch Bar、语音和本机登录接到伴侣进程，行为与现在一致。
4. Windows 微信分享目标，以实机验证为准。
