# ADR 0002：12 个固定分享槽

状态：Accepted（2026-10-29）。

## 背景

macOS 的微信「转发 → 其他应用」只列出已注册的分享扩展（appex）。扩展必须在构建时签名并随宿主注册，运行时不能凭空创建；用户启用的 Bot 数量和名字会变化。

## 决定

- 预建 **12 个槽**，每个槽是一个独立签名的 appex，共用一个扩展程序。
- 每个启用的接收 Bot 占一个槽；槽里写显示名、头像、Bot id、generation。
- 第 13 个起不占槽，仍可用悬浮输入框/快捷指令/拖放。
- 只切换槽的启用状态可以只改显示；改名字、头像、增删 Bot 需要重建宿主、重签、重新注册。
- 宿主放在普通文件夹 `~/Applications/Grok Bot Anywhere Menu/Contents/Helpers`，不嵌在另一个 App 里（否则系统给占位图标）。

## 后果

- 菜单稳定、可预测；代价是 12 个上限和“更新后重开微信”。
- 微信缓存旧菜单是常态，UI 必须提供“更新转发菜单”与说明。
- 每个槽独立签名，签名失败要保留上一份可用宿主，不能把菜单弄没。
- Windows 没有等价机制；不假装移植。
