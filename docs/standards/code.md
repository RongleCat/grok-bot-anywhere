# 代码规范

状态：Current。规则来自这个仓库已经踩过的坑；新增规则要能指向具体文件或事故。

## 改动边界

| 规则 | 检查点 |
| --- | --- |
| 一个改动只服务一个目标 | 行为变化都有理由；顺手重构另开提交 |
| 修复覆盖同类问题 | 用 `rg` 找同形状的调用/分支，不只修报告里的那一个 |
| 改动走完整条路径 | 从入口到落库到 UI 状态；不要只改中间一个函数 |
| 失败读不到 = unknown | 不把解析失败当空/无/相等；保留上次好值，写坏前备份 |
| 别人的值从别人那里来 | 写 Grok Bot 的字段就从它的真实数据/客户端取，不猜字段名 |

## 状态与并发

- 服务进程是唯一写入者；主进程/渲染层不写 SQLite。
- 同一 Bot 发送串行；不同 Bot 可并行。
- 账号切换前 `assertIdle`；切换用 generation 让旧回调失效。
- 不在持锁时做可能阻塞的 I/O；先准备数据再交接。
- 任何新增 goroutine/定时器/子进程都要有停止路径，测试结束前停掉。

## 错误

- 对外只给稳定 `UPPER_SNAKE` 错误码；原始 SDK/HTTP/文件错误不进渲染层。
- 不把“结果不明确”写成“失败”；`SEND_UNCONFIRMED` 必须保持。
- 不自动重试发送；重试是用户动作。
- 日志不写 token、cookie、文件内容、Bot 私密正文。

## 跨平台

- 平台判断集中在 `desktop/src/shell/`、`desktop/src/share/`、`native/`；业务逻辑不散落 `process.platform`。
- macOS 有原生伴侣；Windows 必须用原生文本框，不能用浏览器 textarea 冒充；Linux 未支持。
- 路径用 `join`/`path`，不拼字符串；文件权限在创建时设置（`0600`/`0700`）。
- 跨平台改动至少跑一个非目标平台的构建/单测；UI 行为要在目标平台实机验证。

## 渲染层

- 无 Node、无凭据；新增能力走 preload + 主进程白名单。
- 用户可见字符串必须中英双语。
- 不用原生 `<select>` 做重要选择；保持应用内控件一致。
- 点击不滚动页面；不用彩色左边条表示状态。

## 依赖

- Electron 运行时依赖只有 `grok-bot-sdk` 与头像引擎 tarball；不要偷偷引入同名公共包。
- `packages/client-protocol` 零依赖；不要为一个小功能引入框架。
- 升级 Electron/SDK 要单独提交，附构建与测试证据。
