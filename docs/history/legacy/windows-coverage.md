# Windows coverage

Walkthrough of the features that are not Mac-only. This machine is macOS, so the Windows checks are the shipped functions and their tests, not a live Explorer window or a live WeChat share sheet.

以下均未在 Windows 实机验证。

| Feature | Status | What shipped |
| --- | --- | --- |
| 微信分享菜单 | unsupported-with-reason | WeChat on Windows has no share-extension host like the macOS `GrokBotShare` appex. The desktop app does not register a Windows WeChat share target, and it does not pretend the Mac menu was ported. The practical substitutes are the Explorer context menu, dropping a ZIP on a Bot, and the floating composer. |
| Explorer context menu | implemented-not-verified-on-windows | `explorerTargets` lists only bots whose 接收转发 (`enabled`) is on, in settings order. The parent verb is `HKCU\Software\Classes\*\shell\GrokBotAnywhere` with `MUIVerb` and `ExtendedSubCommandsKey=GrokBotAnywhere.Menu`. Child verbs live under `HKCU\Software\Classes\GrokBotAnywhere.Menu\shell\01_<botId>` and each one has a `command`. A new tree is written before the old parent is deleted; a failed `reg` call deletes the keys that write created. With no enabled Bot, or when Settings turns the menu off, the app only deletes its own keys, including the older `SubCommands` layout under the same parent. The command is `--explorer-forward --bot=<id> -- "%1"`. `createExplorerBatch` waits 800ms. A second Windows instance passes its original `process.argv` through the single-instance payload because Chromium can split `--bot <id>`. A cold start from that flag does not open the main window. A Bot that is really off shows “没有开启接收转发”. A roster that is not loaded yet, or a signed-out account, waits up to 15 seconds and then says the account is still connecting, or asks you to sign in. Rejections append one redacted JSON line to `userData/logs/explorer-forward.log`. The verb is on files only (`*\shell`), not folders. Windows caps a multi-selection at about 15 items. On Windows 11 it is under Show more options. The item has no icon. None of this has been checked on a Windows machine. |
| 悬浮输入框 | implemented-not-verified-on-windows | `floatingComposerTraits('win32')` keeps the composer off the taskbar, always on top, transparent, and sets `thickFrame: false`. The foreground window handle is read before the composer is shown. If that window is Explorer, its selection is read afterward and appended only when the open token and Bot still match. Windows keeps a PowerShell process running for this composer. The app compiles it once after startup, and enterprise security software may warn about that process. On Windows 11, a multi-tab Explorer window may return the first tab's selection. Bringing the selection across has not been verified on a Windows machine. |
| 命令行 | implemented-not-verified-on-windows | `enableCli({platform:'win32'})` writes `grok-bot.cmd` (CRLF, code page saved and restored, `set "GROK_BOT_CONFIG_DIR=..."`, runtime existence check, `ELECTRON_RUN_AS_NODE`) and a UTF-8 BOM `grok-bot.ps1` that only calls that cmd. The user Path is read and written through PowerShell on `HKCU\Environment` (`GetValue` with `DoNotExpandEnvironmentNames`, `SetValue` as `ExpandString`). The new value is passed in an environment variable, and the script prints UTF-8. A missing value is the sentinel `__MISSING__` and is created; any other read failure throws `CLI_INSTALL_FAILED` and does not write. A directory this app adds is appended at the end, the marker is kept across later launches, and it is removed only when that marker is set. After a Path write the app broadcasts `WM_SETTINGCHANGE` with an 8 second timeout. A new terminal picks up the command path. CLI credentials go under `%LOCALAPPDATA%\Grok Bot Anywhere\cli`. Not verified on a Windows machine. |
| skills | implemented-not-verified-on-windows | The same install copies the `grok-bot` skill into the global skills directory and links it into Claude Code with a Windows junction. An existing skill or command that this app did not install is left in place (`CLI_COMMAND_EXISTS`). |
| URL 协议 / 快捷指令 | implemented-not-verified-on-windows | Windows launches the registered `grokbotanywhere` protocol with `start "" "grokbotanywhere://open"`, `start "" "grokbotanywhere://compose?bot=<id>"`, or `start "" "grokbotanywhere://send?bot=<id>&text=<text>"`. A cold start from that link does not open the main window first. `send` and `compose` with text run only when that Bot is enabled, its Shortcuts source is on, and an account is signed in. Text from the link is placed in the composer and is not sent until you confirm, even when the Bot mode is direct. The `grok-bot` command is what submits without that confirmation. The link carries no token. macOS Shortcuts uses the same links through Open URL. Native App Intents are not in this build; see “App Intents 可行性” in `orchestration/results/04.md`. Not verified on a Windows machine. |
